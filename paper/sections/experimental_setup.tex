\section{Experimental Setup}

\subsection{Task and Scale}

The reproduction uses the \texttt{all} configuration of \texttt{cais/mmlu} at immutable revision \texttt{c30699e8356da336a370243923dbaf21066bb9fe}. Twenty-four subject-diverse development examples are used for optimization and 24 disjoint validation examples for evaluation. Subjects are ordered by a seeded SHA-256 rule, and committed JSONL snapshots record source indices, example identifiers, and file checksums.

The graph contains one truthful and one adversarial input--output agent (1T1A) and a majority-vote decision node. The original setting uses 200 optimizer iterations, four sampled graphs per iteration, Adam with learning rate 0.1, and 153 validation questions. Our predeclared CPU-feasible baseline uses 12 iterations, batch size four, and the same learning rate. The preferred 3T3A confirmation is deferred because the local pilot is intended to validate the minimum graph.

\subsection{Comparators and Budgets}

Phase 4 compares direct answer, full connectivity, random connectivity with edge probability 0.5, and accuracy-only optimized GPTSwarm. The later proposed-method comparison will add fixed token penalty and BC-GPTSwarm conditions at multiple feasible budgets. Candidate budget ratios remain 0.50, 0.75, and 1.00 of a named reference execution, subject to smoke-test feasibility; they do not affect the baseline runs.

\subsection{Metrics and Ablations}

Primary metrics are MMLU accuracy, mean total tokens, normalized violation $\mathrm{E}[C/B-1]$, absolute budget error, and compliance rate. Secondary metrics are input/output tokens, estimated dollar cost, latency, active nodes and edges, optimization time, and stability across seeds. Planned ablations compare a learned dual variable with a fixed penalty, measured-token cost with edge-count cost, budget levels, dual learning rates, graph scales, and centered versus raw utility.

\subsection{Reproducibility Controls}

The credential-free baseline uses \texttt{qwen2.5:0.5b} through Ollama 0.17.1 at temperature zero with a four-token output cap and model seed 20260918. It runs on Python 3.10.9 and CPU-only PyTorch 2.8.0 on a 16-logical-core Intel system with approximately 16.9~GB RAM. Experiment seeds are 11, 22, and 33. Phase 4 disables response caching because latency is measured. Every raw response, parsed answer, edge mask, token count, latency, failure, optimizer gradient, and learned probability is logged.

This local model is not numerically comparable to the original GPT-4 Turbo-era endpoint. Results are therefore a controlled behavioral reproduction. The complete deviation log, pinned dependencies, prompts, configurations, and commands are versioned with the code.
